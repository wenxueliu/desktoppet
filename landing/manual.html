01 / GETTING STARTED

启动与第一次见面

两分钟认识你的新桌面伙伴。

Desktop Pet 有两种运行方式：直接使用打包好的安装包（下载后双击安装，打开即可使用），或者在开发模式下运行 npm run dev 以 Electron 方式启动。

首次启动后，你会在桌面角落看到一个 320×320、透明背景、无边框、默认置顶 的宠物窗口。它安静地待在那里，不会抢占你的任务栏或窗口切换列表。

  1. 启动应用 —— 打开安装好的 App，或执行 npm run dev。
  2. 找到你的宠物 —— 它会出现在屏幕角落，直接拖拽即可移动到任意位置。
  3. 打开控制面板 —— 右键点击宠物（默认规则）或使用系统托盘图标。
  4. 调整设置 —— 面板左侧分区：总览、资产、动画、规则、显示、系统。
  5. 保存即生效 —— 配置会写入本地文件，宠物窗口实时重新加载，无需重启应用。
Tip 所有配置都保存在本机的 config.json 中，不会上传到任何服务器；控制面板是一个独立的 960×680 标准窗口，和宠物窗口完全分离，关闭面板不会影响宠物的显示。

02 / OVERVIEW

界面总览：看它在想什么

调试规则最有用的一页。

「总览」是排查问题的第一站。它展示当前激活的宠物包信息，以及三块实时状态：

当前动画

正在播放的动画名称和缩略图预览，用来确认动作有没有真的切换。

最近触发的规则

最近命中的规则名称、执行的动作摘要，以及触发时间，一眼看出是哪条规则生效了。

事件时间线

最近 8 条事件（来自最近 40 条事件的循环缓冲区），用来确认你的操作有没有被系统捕捉到。

举个例子：如果你配置了一条「鼠标靠近 3 秒后打招呼」的规则却没反应，先来总览页看看 mouseMove / mouseStill 事件有没有出现在时间线里——如果事件都没有被记录，说明问题出在条件筛选上，而不是动作本身。

03 / ASSETS

资产管理

素材库、petpack 导入与导出都在这里。

「资产」标签页做两件事：管理当前宠物包里的素材文件，以及导入/导出整份 .petpack（本质是包含 manifest.json 和素材文件的 ZIP 包）。

素材库会列出每个文件的类型、大小，以及被哪些动画或规则引用——被引用的素材会有提示，避免你误删正在使用的文件。

限制项 数值
支持格式 .gif .webp .webm .mp4 .mov .png .svg
单文件大小 最大 50 MB
单个 petpack 大小 最大 200 MB
ZIP entry 数量 最多 256 个
符号链接 不允许，会被直接拒绝

导入 petpack 的过程：校验 ZIP 结构与大小 → 安全检查（拒绝符号链接、越权路径）→ 校验 manifest.json → 原子安装（先解压到临时目录，再备份旧包，最后原子替换；任何一步失败都会自动回滚，不会破坏现有宠物包）。

导出 petpack 会把当前素材，与你在面板里编辑过的动画、规则合并进 manifest，重新校验后打包成新的 .petpack，就可以发给其他人了。

Security petpack 不包含也不会执行任何脚本，只有 manifest.json 和白名单格式的素材文件——导入别人做的宠物包是安全的静态资源操作。

04 / ANIMATIONS

动画设置

默认动画、动画剪辑与关键帧。

一个宠物包至少要有一个「默认动画」，其余都是「剪辑」，通过规则动作切换播放。每个动画都有一个唯一 UUID，规则动作通过这个 ID 引用对应剪辑——改动画的名字不会影响任何规则。

类型 说明
default 默认待机动画，只能用于 animations.default，没有互动时一直播放。
oneshot 一次性动画，通常配置 durationMs，播放结束后自动回到默认动画。适合点击反馈。
loop 循环动画，不依赖时长自动停止，通常由其他规则或退出动作负责切走。适合拖拽中、持续状态。
keyframe 通过 0-1 的 progress 值控制播放进度，配合 keyframes 映射表实现"鼠标从哪个方向靠近，宠物看向哪里"之类的效果。

视频素材（.webm / .mp4 / .mov）还可以开启绿幕抠图，把纯色背景变成透明：

Green Screen 
{
  "greenScreen": {
    "enabled": true,
    "color": "#00ff00",
    "tolerance": 0.35,
    "softness": 0.08
  }
}

color 是要抠除的背景色，tolerance 控制颜色匹配的容差范围，softness 控制边缘过渡的柔化程度——数值越大，抠图边缘越柔和但也越容易吃掉主体的颜色。

05 / RULES

触发规则

让宠物对世界做出反应的核心机制。

规则标签页里可以新建、启用/禁用、排序、复制和删除规则；保存前面板会做基本的冲突检查（例如多条高优先级规则互相打断），并给出提示。

字段 作用
conditions 触发条件数组，见下方「规则编写实战」。
priority 数字越大越优先。规则按优先级从高到低排序匹配。
cooldownMs 本条规则再次触发前的最短间隔，避免被连续刷。
continuous true 时绕过冷却，用于持续更新场景（如根据鼠标角度不断刷新朝向）。
actionStrategy sequence（默认，按顺序执行全部动作）或 random（随机挑一个执行）。
stopOnMatch 默认 true：匹配到这条规则后不再继续往下找其他规则。
state 状态型规则专用，定义退出条件与退出动作，见「规则编写实战」。

条件分两种：默认「必须条件」——需要在 conditionWindowMs（默认 3000ms）时间窗内全部出现才算匹配； 标记 required: false 的是「可选条件组」——只要其中任意一个出现即可。

06 / DISPLAY

显示设置

宠物在桌面上「看起来」的样子。

设置 范围/说明
缩放（Scale） 50% - 150%，调整宠物窗口的显示大小。
透明度（Opacity） 50% - 100%，让宠物更融入桌面背景。
始终置顶（Always on Top） 开启后宠物窗口始终显示在其他窗口之上。
鼠标穿透（Mouse Passthrough） 开启后鼠标点击会「穿过」宠物窗口，作用到桌面或下层窗口，适合完全不想被打扰的场景。
重置位置（Reset Position） 一键把宠物挪回配置中记录的默认坐标。
注意 开启鼠标穿透后，点击、拖拽等依赖鼠标事件的规则会失效——因为鼠标事件不会再被宠物窗口捕获。

07 / SYSTEM

系统设置

开机启动、语言与日志。

「系统」标签页管理和应用本身相关的设置：开机自动启动、界面语言（目前支持中文/英文，且带自动回退——找不到翻译会回退到英文，再回退到 key 本身，不会出现空白），以及运行日志。

日志区域可以开关日志记录、调整级别（trace / debug / info / warn / error）、选择查看某个日志文件、打开日志所在目录、刷新或清空日志——遇到问题时这是最快的排查入口。

08 / RULE RECIPES

规则编写实战

条件、动作、以及六个可以直接抄的例子。

面板里的规则编辑器和 petpack 的 manifest.json 里的 triggerRules 本质是同一份 JSON 数据模型——面板 UI 只是给这份 JSON 套了一层表单。熟悉字段之后，两种方式都可以用。

分类 类型
指针 click doubleClick rightClick mouseEnter mouseLeave mouseMove mouseStill
拖拽 dragStart dragging dragEnd
持续时长 hoverDuration idleDuration
计时器 timer randomTimer
系统/生命周期 appLaunch packageLoaded pomodoroComplete
常用过滤字段 运算符
isInsidePet distanceToPetCenter distanceToPetBounds speed direction angleToPetProgress isMovingTowardPet isMovingAwayFromPet dragDistance dragDurationMs elapsedMs currentHour = != > >= < <= between in notIn

动作类型：playAnimation setKeyframeProgress showMessage randomMessage changeScale changeOpacity movePet pomodoroTimer hidePet showPet resetPosition openPanel

示例一 · 点击打招呼

点在宠物身上，播放一次点击动画，然后随机说句话。

JSON 
{
  "id": "click-greeting",
  "name": "点击打招呼",
  "enabled": true,
  "conditions": [
    { "type": "click", "filters": [
      { "field": "isInsidePet", "operator": "=", "value": true }
    ]}
  ],
  "priority": 50,
  "cooldownMs": 1000,
  "actions": [
    { "type": "playAnimation", "animation": "<click-clip-uuid>", "durationMs": 900 },
    { "type": "randomMessage", "messages": ["Hi there!", "又来啦"], "durationMs": 1800 }
  ]
}

示例二 · 鼠标靠近就抬头

鼠标进入宠物区域时播放一次互动动画。

JSON 
{
  "id": "hover-greeting",
  "name": "悬停互动",
  "enabled": true,
  "conditions": [{ "type": "mouseEnter" }],
  "priority": 30,
  "cooldownMs": 1000,
  "actions": [
    { "type": "playAnimation", "animation": "<click-clip-uuid>", "durationMs": 900 }
  ]
}

示例三 · 拖拽中切换动画

开始拖拽和拖拽过程中都播放循环动画，interruptCurrent 保证立刻打断当前动作。

JSON 
{
  "id": "dragging",
  "name": "拖动中",
  "enabled": true,
  "conditions": [
    { "type": "dragStart", "required": false },
    { "type": "dragging", "required": false }
  ],
  "priority": 90,
  "interruptCurrent": true,
  "actions": [
    { "type": "playAnimation", "animation": "<drag-loop-uuid>" }
  ]
}

示例四 · 空闲太久去睡觉

用 idleDuration 搭配 elapsedMs 过滤器，判断鼠标多久没动。

JSON 
{
  "id": "idle-sleep",
  "name": "休息状态",
  "enabled": true,
  "conditions": [
    { "type": "idleDuration", "filters": [
      { "field": "elapsedMs", "operator": ">=", "value": 60000 }
    ]}
  ],
  "priority": 5,
  "cooldownMs": 10000,
  "actions": [
    { "type": "showMessage", "text": "Zzz...", "durationMs": 1800 }
  ]
}

示例五 · 状态型规则：靠近问候，离开恢复

状态型规则适合持续条件：鼠标靠近并停留 3 秒后进入「问候」状态，播放跟随鼠标角度的关键帧动画；离开并停留 3 秒后通过 state.exitConditions / state.exitActions 自动回到默认动画。

JSON 
{
  "id": "near-pet-greeting",
  "name": "靠近问候",
  "enabled": true,
  "conditions": [
    { "type": "mouseMove", "sustainMs": 3000, "filters": [
      { "field": "distanceToPetCenter", "operator": "<=", "value": 300 }
    ]}
  ],
  "priority": 80,
  "continuous": true,
  "actions": [
    { "type": "setKeyframeProgress", "animation": "<keyframe-clip-uuid>", "progressFrom": "angleToPetProgress" }
  ],
  "state": {
    "exitConditions": [
      { "type": "mouseMove", "sustainMs": 3000, "filters": [
        { "field": "distanceToPetCenter", "operator": ">", "value": 360 }
      ]}
    ],
    "exitActions": [
      { "type": "playAnimation", "animation": "<default-animation-uuid>" }
    ]
  }
}
angleToPetProgress 方向约定 progress 值
上方 0
右侧 0.25
下方 0.5
左侧 0.75

示例六 · 番茄钟结束后提醒

配合 pomodoroTimer 动作和 pomodoroComplete 条件，做一个安静的专注提醒。

JSON 
{
  "id": "pomodoro-done",
  "name": "专注时间结束",
  "enabled": true,
  "conditions": [{ "type": "pomodoroComplete" }],
  "priority": 60,
  "actions": [
    { "type": "showMessage", "text": "休息一下吧～", "durationMs": 2400 },
    { "type": "playAnimation", "animation": "<click-clip-uuid>", "durationMs": 900 }
  ]
}
Tip 多个动作默认按 actions 数组顺序依次执行；把 actionStrategy 设为 "random" 会从动作列表里随机选一个执行，适合「随机小动作」类的规则。

09 / PETPACK AUTHORING

素材与宠物包制作

从一堆素材文件，到一份可以分享的 .petpack。

推荐的项目目录结构：

Folder 
my-cute-pet/
├── manifest.json
└── assets/
    ├── idle.svg
    ├── click.gif
    ├── drag.webp
    └── follow.webm

素材路径必须是相对路径（例如 assets/idle.svg），不能使用绝对路径、反斜杠、URL、. 或 ..。

  1. 准备素材 —— 至少准备一个默认待机动画，格式见「资产管理」一节的支持列表。
  2. 建立目录 —— 项目根目录 + assets/ 子目录。
  3. 编写 manifest.json —— 见下方最小示例，声明包信息、默认动画和动画剪辑。
  4. 压缩成 ZIP —— macOS/Linux 用 zip，Windows 用 Compress-Archive。
  5. 改扩展名 —— 把生成的 .zip 改成 .petpack。
  6. 在面板导入 —— 「资产」标签页 → 导入 petpack → 选择文件。
macOS / Linux 
cd my-cute-pet
zip -r ../my-cute-pet.petpack .
Windows PowerShell 
Compress-Archive -Path * -DestinationPath ..\my-cute-pet.petpack

manifest.json 最小可用示例：

manifest.json 
{
  "schemaVersion": 1,
  "packageId": "my-cute-pet",
  "name": "My Cute Pet",
  "version": "1.0.0",
  "author": "Your Name",
  "description": "A tiny desktop companion.",
  "animations": {
    "default": {
      "id": "11111111-1111-4111-8111-111111111111",
      "name": "Idle",
      "asset": "assets/idle.svg",
      "type": "default"
    },
    "clips": []
  },
  "triggerRules": []
}
字段 是否必填 说明
schemaVersion 必填 当前为 1。
packageId 必填 包 ID，建议 kebab-case。
name 必填 显示名称。
version 必填 版本号。
animations.default 必填 默认动画，动画 ID 必须是 UUID。
animations.clips 必填 动画剪辑数组，可以为空数组。
author / description / homepage / license / preview 可选 展示与分发相关的元信息。
triggerRules 可选 随包附带的默认规则，格式见「规则编写实战」。
制作建议 所有动画剪辑最好用统一的画布尺寸和锚点，切换时才不会「跳一下」；待机动画尽量用体积小的循环素材（SVG 或压缩过的 GIF/WebP），减少常驻的 CPU/内存占用； keyframe 类型如果用视频做，帧数越多，跟随鼠标转动时越顺滑。

10 / FAQ

常见问题

遇到问题先看这里。

为什么 petpack 导入失败？

常见原因：manifest.json 不在 ZIP 根目录；缺少 schemaVersion、packageId、 animations.default 等必填字段；动画 ID 不是 UUID；manifest 引用了不存在的素材；素材路径包含 ..、绝对路径或反斜杠；文件格式不在支持列表；文件大小、包大小或文件数量超过限制。

为什么动画不播放？

依次检查：动画的 asset 是否指向真实存在的文件；规则动作里的 animation 是否是正确的 UUID； 规则的 enabled 是否为 true；条件过滤是否过窄（比如 isInsidePet 或距离阈值不满足）； 是否有另一个更高优先级的 loop 规则一直在打断它。可以先去「总览」页看事件时间线确认事件有没有被捕捉到。

怎么做透明背景？

推荐使用带透明通道的 PNG、WebP、GIF 或 WebM。MP4/MOV 的透明能力依赖具体编码和平台支持，稳定性不如 WebM。 如果只有纯色背景的视频素材，可以用「动画设置」里的绿幕抠图功能。

petpack 里可以包含脚本吗？

不可以。petpack 只包含 manifest.json 和白名单格式的素材文件，不会执行任意脚本，这也是它能安全分享的前提。

可以同时安装多个宠物包吗？

可以导入并保留多个包，但当前配置中只有一个 currentPackageId 处于激活状态，也就是同一时间只有一只宠物在桌面上活动。

11 / ROADMAP

未来计划：社区广场

规则和宠物包的分享，现在架构已经准备好了。

以下内容还没有开发，是基于现有架构推演出来的设计方向——如果你对这件事感兴趣，欢迎在 GitHub 上提出想法或参与建设。

资源包广场规划中

集中浏览社区制作的 .petpack，一键安装到本地。

  • 按标签（画风、动物种类、动画数量、文件体积）搜索与筛选
  • 预览动图、作者信息、版本变更记录
  • 下载量、收藏、评分，帮助发现优质内容
  • 「一键导入」本质仍是现有的下载 → 校验 → 原子安装流程，不需要新的信任模型

规则广场规划中

分享单条规则 JSON，而不是整份宠物包——专门用来交流「玩法」。

  • 按条件类型、动作类型筛选，方便按玩法找灵感
  • 「复制到当前包」把规则追加进本地 triggerRules
  • 导入时自动做动画引用检查：规则里引用的动画剪辑如果本地没有，会提示先补上对应素材再启用
  • 适合分享像「鼠标画圈会转圈圈」这类不需要换整套素材的巧妙规则

现有架构里，已经为这两个广场准备好的基础设施：

  • petpack 本身是自包含的 ZIP + JSON manifest，天然适合上传、下载和版本管理；
  • manifest 校验、素材格式白名单、大小限制、无脚本执行——分享内容默认是安全的静态资源；
  • schemaVersion 字段已经为未来的格式演进留了扩展空间；
  • 规则的 JSON 结构和面板 UI 是同一份数据模型，规则广场不需要再设计一套「半成品」格式。
还在想的问题 内容审核与举报机制、跨版本 schemaVersion 兼容策略、以及规则/资源包的信誉与评价体系——这些还需要更多讨论，欢迎一起设计。
